Fluxo

Como é hoje vs. como ficaria com CISa

Hoje — OMIE

  1. Financeiro gera arquivo CNAB no OMIE.
  2. Arquivo é transmitido ao Santander pelo fluxo já conhecido.
  3. Santander processa e devolve retorno (.txt).
  4. OMIE lê o retorno e faz baixa automática.

Proposto — NetSuite + CISa

  1. NetSuite gera arquivo e salva em pasta monitorada (OUTBOX).
  2. CISa/AFT transmite o arquivo ao Santander automaticamente.
  3. Santander processa e devolve retorno no formato .RET.
  4. CISa disponibiliza o arquivo .RET (INBOX) para leitura do NetSuite.

Requisitos Técnicos

O que a CISa exige para funcionar

Requisitos mínimos do servidor

  • Windows 64 bits
  • Processador 1 GHz ou superior
  • 256 MB de memória livre
  • 200 MB de disco + espaço para logs
  • Porta 9000 liberada
  • Executar instalação como Administrador

Configurações obrigatórias

  • Modo de operação: Automático
  • Caixa de entrada e saída: código GE (enviado por e-mail)
  • Ativação do Token: usuário + código de ativação
  • Senha: 8+ caracteres, maiúscula, minúscula e especial
  • Tarefa agendada no Windows (configurar data de início)

URLs de conexão Santander

  • cisa.santander.com.br/cisa/asl/ASLIntegration
  • cisa.santander.com.br/cisa/asl/AFTServlet
  • Testar conectividade via CMD (ping / tracert)

Arquivos de LOG (monitoramento)

  • aftservice-0-0.log
  • AFTClient_Config.xml
  • Em caso de erro, encaminhar esses arquivos ao Santander
  • Local: C:\Program Files\Santander ASL Automated File Transfer

Estrutura de diretórios — C:\Santander\AFTData

Próximos Passos

Roteiro de homologação

1

Resolver pendências com Santander

Aguardar respostas sobre coexistência com OMIE, layout .RET e SLA. Não iniciar instalação antes dessas definições.

2

TI liberar porta 9000 e validar conectividade

Testar acesso às URLs do Santander via CMD (ping/tracert) antes de instalar o CISa.

3

Instalar em servidor dedicado Windows 64-bit

Executar como Administrador. Configurar modo automático, caixas de entrada/saída (código GE) e ativar Token.

4

Configurar Agendador de Tarefas

Ajustar data de início e repetição a cada 15 minutos. Monitorar logs após primeiro ciclo.

5

Homologar em paralelo (sem desligar OMIE)

Testar pagamento, cobrança, retorno (.RET), rejeição e baixa ponta a ponta com NetSuite.

6

Validar .RET ponta a ponta

Confirmar que o arquivo sai do Santander/CISa e é aceito corretamente pelo NetSuite.

7

Definir governança e plano de rollback

Financeiro opera; TI sustenta o servidor; Santander suporta a conexão. Manter OMIE ativo como contingência.

Conclusão

Leitura executiva para decisão

A CISa não deve substituir imediatamente o processo atual.
Ela deve entrar como camada adicional durante a homologação do NetSuite, com OMIE ainda ativo como fallback.

A ferramenta exige preparação técnica de TI.
Servidor Windows dedicado, porta 9000 liberada, instalação como administrador, token ativado e agendamento configurado são pré-requisitos antes de qualquer teste.

Ponto positivo: sem custo adicional confirmado.
Aguardar respostas pendentes do Santander (SLA, layout .RET, coexistência com OMIE) antes de definir cronograma de implantação.
